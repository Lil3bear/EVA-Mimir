# Evidence-to-Response and Revision Ledger

Independent engineering extension of 丁霄汉's user-supplied rebuttal advice, https://zhuanlan.zhihu.com/p/602024489. It connects the response Skill to Autopaperreview's eight modules, not to an assumed conference policy.

## Route the Concern

| Concern | Owner | Rebuttal's contribution |
| --- | --- | --- |
| Unclear motivation/contribution | writing + macro structure | Explain the actual final method and point to the concrete rewrite |
| Unsupported guarantee or attribution | claims + review | Test the strongest defense; narrow wording or keep the needed control open |
| Unfair baseline or missing comparison | claims + blind | Ask what contrast would discriminate the claim; use only actual protocol/results |
| Misattributed or missing literature | citations | Verify identity and relevant full-text support before defending a novelty claim |
| Undefined symbol or execution rule | math | Supply the actual definition when available; do not invent a threshold |
| Unreproducible setting | blind | Provide the real version, split, budget and aggregation, or state exactly what is unavailable |
| Anonymity, page or response rule | venue | Check the actual year/track/stage; do not import rules from another venue |
| Broken figure, citation or build | latex | Name the source edit, build result and actual visual check separately |

## Concern Record

Reuse existing IDs. Store reviewer/source and full concern; fair interpretation; exact current manuscript quote; direct answer; supporting and contrary evidence; chosen position; source change; verification; unresolved requirement. Real reviews, simulated AI reviews and author comments remain distinct sources.

Possible positions: agree and correct; factual disagreement with evidence; clarify an ambiguous explanation; bounded scope disagreement; evidence missing. A reviewer can be partially right. Do not collapse these positions into automatic apology or automatic defense.

## Completion

Track proposed, applied in source, compiled, visually checked and scientifically resolved separately. If the request was 'show the selector's causal benefit', a wording change that removes the claim is a valid scope repair but not a completed ablation. Preserve that distinction in the response and the comment log.

Do not promise a dataset result, reorganization or figure repair without a concrete plan. Use completed tense only for verified work. A future plan should identify what changes, where and how success will be checked; it must not claim a predicted favorable outcome.

For real response drafting, verify the supplied venue constraints and keep any confidential chair draft separate. For manuscript-only revision, use this ledger as a defensive check and do not fabricate reviewer IDs, votes or an official rebuttal.
