# Figure Layout

Source: [PaperBanana, Figure 1 layout patterns](https://paper-banana.org/zh/blog/figure-1-layout-patterns), accessed 2026-10-19. The following taxonomy is a short independent summary; example artwork belongs to its original authors and is not included.

Choose the layout from the message: before/after for a substantiated contrast; layered framework for responsibilities; pipeline with an inset for a key internal mechanism; color-coded architecture for interacting modules; decision tree for alternatives; worked example for a concrete transformation. A wide aspect ratio is an option, not a conference requirement.

Project-specific implementation rules:

- Write the takeaway before placing elements. Make the novel supported mechanism visually dominant; do not emphasize every box.
- Establish one reading direction and consistent arrow semantics. Keep development/admission outside frozen evaluation. Visually distinguish implementation from an unverified design proposal.
- Group by scientific role, not by available space. Align elements to a grid; use whitespace instead of decorative containers. A loop must identify what returns, when and why.
- Encode roles with a small consistent palette plus labels or line styles. Avoid relying on color alone. Use white background and restrained pastel fills with dark text.
- Keep module labels short. Put qualifications in a caption, not tiny paragraphs. Check at the actual single/two-column width, not only on a large screen.
- Revise layout after content validation. Check arrow crossings, ambiguous endpoints, clipping, reading order, grayscale readability and consistency with all other figures.
