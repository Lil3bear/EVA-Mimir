# 立足点 → RCE 转化检查清单

> 已获得认证、文件读写或配置修改能力，但尚未证明命令执行时使用。每一步都必须在当前实例验证结果。

## 1. 先确认能力边界
- 保存当前 Cookie/token、响应状态、可读/可写路径和权限；用一次无害请求确认会话仍有效。
- 根据产品指纹加载对应 playbook 或本地 CVE 条目；知识条目只是候选路线，不是成功证明。
- 不把 Observer 的具体 payload、旧地址或历史方法当作事实。

## 2. 收敛验证次数
- 同一端点、同一参数结构连续 3 次没有新响应证据，就记录 failure boundary，换到另一类能力（文件读写、模板、反序列化、任务/插件或服务间调用）。
- 配置修改后只按当前产品文档/响应确认触发方式；不要盲等固定时间或重复重启。每次修改后读取或请求验证配置是否真的生效。
- 黑名单绕过按类别验证（拼接、编码、替代 API 等），每类最多一个可解释的候选，并记录判定。

## 3. 成功判据
- RCE 必须有明确的命令输出、身份变化、可控文件或等价的当前目标证据；HTTP 200、错误页或回显字符串本身不算。
- 一旦获得命令执行，立即确认身份/系统/网络，再按当前证据收集 flag、配置和内网资产；不要重新枚举已经判死的入口。
- 未获得成功判据时继续换路或按控制预算停止；不要因为 Skill 中存在示例命令就直接复制执行。
