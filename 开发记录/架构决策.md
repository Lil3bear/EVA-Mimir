## 架构图

```
宿主机进程（Python）
  ├── Host 主进程
  │     ├── 启动 Docker 容器（docker run）
  │     ├── stdin/stdout JSONL 通信管道
  │     ├── Host Bridge Handler（flag 提交、题目状态）
  │     └── rich TUI 界面
  │
  └── 数据目录（volume 挂载进容器）
        ├── memory/entries/*.json
        ├── ideas/index.json
        └── submissions/*.json

Docker 容器（Linux, linux/amd64）
  ├── Solver Agent（主线程）
  │     ├── ReAct 循环（LLM → tool_call → 执行 → 结果拼回）
  │     ├── 工具：bash、read、write、grep、find
  │     ├── 工具：challenge_submit_flag（经 Host Bridge）
  │     ├── 工具：memory_add / memory_list
  │     └── 工具：idea_list / idea_add
  │
  └── Observer（sidecar，每 6 轮触发）
        ├── 独立 LLM Session
        ├── 审查 Solver 最近行为
        ├── 更新 Memory/Ideas 看板
        └── 必要时向 Solver 发纠偏消息
```

---

## 关键设计原则

1. **工具层做硬约束**：角色边界靠工具集实现，不靠 Prompt 劝说。Observer 没有 bash，Solver 没有 idea_update。
2. **控制权在 Host 侧**：flag 提交、状态管理全在 Host 进程，容器只是执行沙箱。
3. **共享状态走文件**：Memory/Ideas 存宿主机 JSON 文件，volume 挂载进容器，原子写入 + 文件锁。
4. **Context 管理优先**：Solver 初始任务只注入最近 N 条 memory/ideas 摘要，不是全量。
5. **Skills 按需加载**：system prompt 只放 Skill 的一行 description，LLM 用 read 工具按需加载全文。

## challenge.json 格式（初步设计）

```json
{
  "id": "easy-login",
  "name": "Easy Login",
  "category": "web",
  "difficulty": "easy",
  "description": "找到管理员账号登录后台，获取 flag",
  "url": "http://challenge.ctf.local:8080",
  "flag_format": "flag{...}",
  "attachments": [],
  "hints": [],
  "submit_url": "https://ctf.example.com/api/v1/challenges/1/attempts",
  "api_key": "your_ctfd_api_key"
}
```

`submit_url` 和 `api_key` 为可选字段，不填则 Agent 找到 flag 后只输出到终端。
