## 暴露的系统性问题

### 🔴 P0：max_rounds=100 对所有难度一刀切

**现象**：easy 题（a-05）花了 100 轮 22 分钟没解出。这 22 分钟如果分给其他题会更有价值。

**建议**：
- easy: max_rounds=30（~5 分钟）
- medium: max_rounds=60（~15 分钟）
- hard: max_rounds=100（~25 分钟）
- 或者按时间限制：easy 5 分钟、medium 15 分钟、hard 30 分钟

### 🔴 P0：串行执行太慢（总耗时 4.5 小时）

**现象**：SOLVER_MAX_PARALLEL=1，18 题串行跑，失败题每题浪费 20-30 分钟。

**计算**：
- 9 题解出平均 3.5 分钟 = 31.5 分钟
- 9 题失败平均 26 分钟 = 234 分钟
- 总计 ~265 分钟 ≈ 4.5 小时

**如果用并行 max_parallel=3**：
- 9 个失败题并行化后，理论总耗时 ~2 小时
- 如果加上 max_rounds 分级，可以压到 ~1.5 小时

### 🟡 P1：Agent 在已知信息面前"视而不见"

**a-05 典型案例**：
- 第 70 轮已经读到 config.php，里面明文写着 `admin/admin123`
- 但 Agent 继续在 LFI 方向上打转（尝试读 /proc/self/environ、Apache 配置等）
- 没有意识到应该用 admin 登录后去 /api/admin/ 下找敏感接口

**根因**：Solver prompt 缺乏"回顾已知信息"的强制检查点。Agent 会陷入当前方向的惯性，忽略已经获取的关键信息。

**建议**：每 20 轮强制注入一次"回顾 Memory 中的已知凭据/路径/信息，是否有未利用的"。

### 🟡 P1：方向循环警告被忽略

**现象**：`download.php?id=` 被方向循环检测器标记了 13 次警告，但 Agent 完全忽略了警告文本，继续用相同结构请求。

**根因**：
1. 方向循环检测的 URL 模式提取过于粗暴——`download.php?id=../config.php` 和 `download.php?id=../../../../etc/passwd` 被当作"同一结构"
2. 警告只是追加到工具输出里，没有强制性约束（不会阻断执行）

**建议**：
1. URL 模式提取需要区分 path traversal 的目标不同
2. 超过 N 次警告后，自动触发 Observer 审查（而不是等 6 轮周期）

### 🟡 P1：security_search 返回编造知识

**现象**：多次 security_search 返回的都是 LLM 编造的通用知识，对具体题目没有帮助。

**建议**：接入真实搜索引擎（Tavily/Serper）作为 P1 优化项。

### 🟢 P2：Observer 纠偏有时被 Solver 忽略

**a-17 案例**：Observer 多次纠偏说"停止 cookie/session 循环，转向 /includes/ 枚举"，但 Solver 只执行了部分，很快又回到旧方向。

**建议**：
1. 纠偏消息注入后，增加"你必须在接下来 3 轮内执行以上方向，否则将被强制终止"的强制约束
2. 或者在注入纠偏后的 3 轮内检查是否执行了纠偏建议
