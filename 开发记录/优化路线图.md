## P0：立即修复

### 1. 移除 Solver 的 `idea_add` 工具

**问题**：`架构决策.md` 里写的是"Observer 没有 bash，Solver 没有 idea_update"，但 `solver/agent.py` 实际注册了 `idea_add`。设计原则和实现矛盾。

**影响**：Solver 可以随意修改攻击方向列表，Observer 精心维护的 ideas 可能被 Solver 覆盖或添加低质量方向。

**修改位置**：`solver/agent.py`

```python
# 删除这两行
idea_tools.IDEA_ADD_TOOL_DEF,        # TOOL_DEFS 里
"idea_add": idea_tools.idea_add,     # TOOL_EXECUTORS 里
```

同时更新 System Prompt，去掉"用 idea_add 记录攻击方向"的描述，改为"攻击方向由 Observer 维护，你只读 idea_list"。

---

### 2. 大工具结果：告诉 LLM 完整文件在哪里

**问题**：当前截断后 LLM 只有头 500 + 尾 3000 字节，不知道完整内容保存在哪里，无法主动查询。

**影响**：比如 `sqlmap` 扫描输出很长，LLM 看到截断后只能靠片段猜，无法用 `grep` 在完整结果里搜特定字段。

**修改位置**：`solver/tools/bash_tool.py` 的截断提示文案

```python
output = (
    f"[输出过长（{len(output)} 字节），已截断]\n"
    f"[完整结果已保存至：/root/workspace/.tool-results/{filename}]\n"
    f"[可用 bash 工具执行 grep/cat 查询完整内容]\n"
    f"[开头 500 字节]\n{head}\n"
    f"... (省略中间部分) ...\n"
    f"[末尾 3000 字节]\n{tail}"
)
```

关键是把文件路径暴露给 LLM，让它能主动 `grep -i flag /root/workspace/.tool-results/xxx.txt`。

---

### 3. Observer 误判 `<title>` 为 flag 信号

**问题**：bash 截断保留头 500 字节，恰好包含 HTML 的 `<head>` 区（含 `<title>flag，我TM来了！</title>`）。Observer 读 memory 摘要时把页面标题当成了 flag 出现的信号，连续 5 轮发送"flag 就在响应里！"的错误纠偏，导致 Solver 20+ 轮空转在"读完整响应"方向。

**影响**：Observer 的误判比 Solver 自己迷路危害更大，因为纠偏有主动干预效果。

**修改方向**：
- Observer 在发 flag 相关纠偏前，必须先验证是否匹配 flag 格式（`NSSCTF{...}` 等），而非检测"flag"关键字是否出现
- 可在 Observer system prompt 里明确写："只有内容符合 flag 格式正则时才报告 flag 发现，页面标题、按钮文字不算"

**修改位置**：`solver/observer/agent.py` system prompt

---

### 4. Observer 纠偏被 Solver 长上下文淹没

**问题**：本次运行 Observer 共发出 7 次纠偏，Solver 几乎没有照做。纠偏消息作为普通 `user` 消息注入，在 40-50 条的对话历史里会被 LLM 的注意力机制忽略，尤其是 Solver 已经有"惯性"的时候。

**修改方向**（可选其一或组合）：
1. 纠偏消息放在最新一轮 `user` 消息的**最前面**，而不是追加到历史末尾
2. 纠偏消息用特殊前缀标记（如 `⚠️ [OBSERVER OVERRIDE]:`），并在 system prompt 里强调"看到此前缀必须立即响应"
3. 触发纠偏时同时做一次**上下文裁剪**，把陷入死路的最近 N 轮对话删除，强制 Solver 从纠偏点重新出发

**修改位置**：`solver/observer/loop.py` 的 `send_correction` 注入逻辑

---

### 5. Solver 缺乏重复操作自检机制

**问题**：本次 Solver 在 binary MD5 collision 的 URL encoding 方向循环了 60 轮（round 12–70），每次换个小细节重试，没有任何机制告诉它"已经尝试过类似操作"。

**修改方向**：给 Solver 一个"死路记录"工具或机制：
- 方案 A（轻量）：在 bash_tool 执行时，对 `(cmd[:50], exit_code, output[:100])` 做指纹，发现与近 10 次重复时在输出里加警告 `[WARNING: 近似命令已执行 N 次，建议换方向]`
- 方案 B（重量）：新增 `dead_end_add` 工具，Solver 自己记录"XXX 方向已验证失败"，system prompt 里要求每 10 轮自查一次 dead_end 列表

**修改位置**：`solver/tools/bash_tool.py`（方案 A）或新增 `solver/tools/deadend_tool.py`（方案 B）

## P1：近期优化

### 3. Observer 防骚扰三层保护

**问题**：Observer 每 6 轮必触发，没有任何去重/冷却保护。如果 Solver 当前正常推进，Observer 会不断打断注入（已在日志中观察到）。

**修改位置**：`solver/observer/loop.py`，在发送纠偏前加三个检查：

```python
# 新增状态变量
self._last_correction_round = 0
self._last_correction_fingerprint = ""

def _should_send_correction(self, content: str, current_round: int) -> bool:
    # 检查 1：题目已完成？
    if self._challenge_solved:
        return False
    # 检查 2：冷却期（距上次纠偏不足 6 轮）？
    if current_round - self._last_correction_round < 6:
        return False
    # 检查 3：内容指纹和上次一样？
    import hashlib
    fp = hashlib.md5(content.encode()).hexdigest()[:8]
    if fp == self._last_correction_fingerprint:
        return False
    self._last_correction_round = current_round
    self._last_correction_fingerprint = fp
    return True
```

### 4. Observer 历史访问：暴露 Solver 原始对话记录

**问题**：Observer 只能看 `on_tool_call` 收集的摘要（每条 300 字），是预处理后的二手信息。判断"Solver 为什么卡住"时准确率受限。

**方案**：把 Solver 的完整对话历史序列化写到一个文件，Observer 用 `read_file` 工具读取。

**修改位置**：

1. `solver/agent.py`：每轮结束后把 `self.messages` 写到 `/root/workspace/.solver-history.jsonl`（只写最近 20 条，避免太大）
2. `solver/observer/agent.py`：在 Observer system prompt 里告知它可以 `read_file("/root/workspace/.solver-history.jsonl")` 查看 Solver 原始记录

---

### 5. 语义引导的上下文压缩

**问题**：当前在 `solver/agent.py:190` 处的压缩策略是朴素滑动窗口——超过 35 条就保留最后 30 条，早期发现全部丢失。

**影响**：解 50+ 轮的复杂题时，第 5 轮发现的关键端点或参数会被截断丢失，LLM 重复走死路。

**方案**：在压缩前先让 LLM 生成一段"当前状态摘要"，注入到压缩后的头部：

```python
if len(self.messages) > 35:
    # 1. 让 LLM 总结当前状态（用便宜模型）
    summary = self._generate_compression_summary()
    # 2. 保留 system + 摘要 + 最近 20 条
    system = self.messages[0]
    tail = self.messages[-20:]
    while tail and tail[0].get("role") == "tool":
        tail = tail[1:]
    self.messages = [system] + [{
        "role": "user",
        "content": f"[上下文已压缩] 当前解题状态摘要：\n{summary}"
    }] + tail
```

摘要 Prompt（让 LLM 必须保留）：
- 当前已确认的漏洞点/突破口
- 所有已获取的凭据、token、session 值
- 当前正在尝试的攻击路线
- 已确认失败的路线（不要重复）

## P2：后续扩展

### 6. 求 Hint 时触发 Observer

**问题**：Solver 调用 `challenge_get_hint` 说明已经卡住，但 Observer 要等下一个 6 轮周期才触发，这段时间 hint 信息没有被整合进 ideas 看板。

**修改位置**：`solver/agent.py` 的工具执行循环

```python
if tool_name == "challenge_get_hint":
    # hint 到了，立即触发一次 Observer（不等 6 轮）
    self.observer.trigger_now(reason="hint_received", hint_content=result)
```

---

### 7. 安全知识搜索工具

**问题**：Skills 只覆盖预先写好的方向，遇到冷门 CVE、特定框架漏洞链时 LLM 只能靠训练数据盲猜。

**方案**：接入搜索 API（Kimi、Tavily、Serper 等），新增 `security_search` 工具：

```python
# solver/tools/search_tool.py
TOOL_DEF = {
    "function": {
        "name": "security_search",
        "description": "搜索安全知识库，适用于需要了解特定 CVE、框架漏洞、绕过技术时",
        "parameters": {
            "query": {"type": "string", "description": "搜索关键词，如 'PHP 7.3 md5 array bypass'"}
        }
    }
}
```

可用接口优先级：Kimi（已有账号）> Tavily（CTF 友好）> DuckDuckGo（免费）

---

### 8. System Prompt 外置为 .md 文件

**问题**：`solver/agent.py:_build_system_prompt()` 中的 prompt 硬编码，不同题目类型（Web/Pwn/Crypto/Reverse）需要改代码才能切换。

**方案**：prompt 存 `prompts/solver.md`（已存在），顶部加 YAML front matter：

```yaml
---
model: "claude-sonnet-4-6-thinking"
observer_model: "claude-haiku-4-5-20251001"
observer_enabled: true
skills:
  - web
  - crypto
tools_blacklist:
  - idea_add
---
你是一名顶尖 CTF 选手...
```

`_build_system_prompt()` 改为从文件读取，解析 front matter 后覆盖 settings.json 的配置。这样可以给不同题目类型维护不同的 prompt 文件，通过 `--prompt prompts/pwn-solver.md` 切换。
