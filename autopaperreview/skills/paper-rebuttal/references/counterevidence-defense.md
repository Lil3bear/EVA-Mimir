# Counterevidence and Defense Playbook

Source inspiration: **丁霄汉**, [Rebuttal](https://zhuanlan.zhihu.com/p/602024489). This is an independently written operational extension. Retain reasoned disagreement, specific corrections and evidence. Reject personal attacks, selective quotation, fabricated experiments and invented consensus.

## Distinguish the Jobs

- Simulated review: adjudicate whether the objection survives the strongest legitimate defense. Do not write an official review response or edit sources without authorization.
- Response preparation: answer actual supplied concerns and obey the verified venue rules. An interview defense can instead prepare spoken answers without assuming conference restrictions.
- Manuscript repair: make authorized changes supported by the available evidence; retain unresolved experiments as unresolved.

## Concern Decomposition

Preserve reviewer/source ID and exact complete concern. Split a compound concern only when its subclaims need different evidence or remedies. Record the factual premise, challenged claim, decision consequence and minimum resolving observation. Do not substitute an easier question.

| Concern | Decisive check | Appropriate evidence | Inadequate defense |
| --- | --- | --- | --- |
| Unclear novelty | Which operation differs from closest relevant method? | Full-text method comparison and attribution | Different name or a longer list of components |
| Component benefit | Can the gain be assigned to this component? | Matched control or bounded mechanistic evidence | Full-system SOTA alone |
| Fairness | Same information, data, tuning and budget? | Actual configs and protocol | 'Other papers use this baseline' |
| Generalization | Are held-out units independent of development? | Split construction and evaluation lineage | Many correlated frames or new random seeds alone |
| Leakage | Does forbidden state cross the evaluated agent boundary? | Active data flow plus run configuration | A diagram that omits a debug path |
| Physical success | Does the task outcome follow from execution? | State/trajectory and independent acceptance predicate | Planner convergence, API success or rendered proximity |
| Efficiency | Which costs and failures are included? | Matched wall-clock/call budget with aggregation | Online cost excluding offline search |
| Missing experiment | Would it distinguish the challenged claim? | Actual completed permitted result or narrowed scope | Promised favorable result |
| Presentation | Is the answer present but hard to locate? | Exact current wording and a concrete rewrite | 'The reviewer did not read carefully' |

## Evidence Grades and Version Binding

Label the basis, not just a confidence adjective:

- Direct: same system version, evaluation setting and claimed outcome.
- Partial: relevant but different population, configuration or capability.
- Implementation: code/config proves a path exists, not that a run succeeded.
- Author report: a historical note or assertion without underlying artifacts.
- Proposed: desired test or mechanism, not existing evidence.

Search supplied appendices, definitions, captions, limitations and actual artifacts for both support and contradiction. Bind the defense to version, input access, comparison budget, denominator and success criterion. Missing artifacts mean 'not verified from available material', not 'never done'. A model's opinion is not evidence.

## Adjudication

Use unambiguous concern-oriented verdicts:

| Verdict | Meaning | Next action |
| --- | --- | --- |
| Objection supported | Current claim exceeds available support or contains a demonstrated defect | Retain finding and specify repair/evidence |
| Objection partial | Defense resolves part but a named residual remains | Narrow the finding to that residual |
| Objection rebutted | Direct evidence answers the actual concern | Remove the scientific complaint; keep clarity issue only if supported |
| Evidence unresolved | Neither the objection nor its defense can be established | State coverage gap, do not upgrade to proven defect |

For each material finding supply: exact claim/location, fair concern, strongest defense, supporting evidence, contrary evidence, verdict, residual and closure test. Stop when the decisive available sources are checked; do not loop until a preferred verdict emerges.

## Answer Construction

Answer first, then evidence, concrete change and residual scope. Reuse exact concern IDs when grouping duplicates. Set response length by decision impact, not reviewer hostility.

**Valid criticism:** 'We agree that [specific defect] limits [claim]. [Verified correction/result]. We have changed [actual location and content]. [Remaining limit].' Use future tense if not applied.

**Factual disagreement:** 'The evaluated policy receives [actual input], while [other state] is limited to [verified boundary]. [Code/config/protocol evidence]. We clarified [actual text].' Do not assert the boundary until the active path is checked.

**Partial defense:** 'The existing experiment supports [narrow result], but does not isolate [mechanism]. We now limit the claim to [scope]; [requested comparison] remains unrun.' A smaller claim can be honest without resolving the original scientific request.

**Scope disagreement:** explain why the request targets a different problem, then check that the paper does not itself promise that broader capability. 'Others omit it' and reviewer praise are not scientific defenses.

## Revision and Defense Readiness

Track textual status separately from scientific status: proposed / applied / compiled / visually checked; experiment pending / artifact available / checked. An acknowledgment or drafted answer does not close a concern. A changed manuscript may reopen an earlier issue if its premise changes.

Prepare short spoken answers when requested: direct answer, strongest evidence, candid boundary, next test. Add a follow-up question that exposes the weakest assumption. For each unverified result prepare an honest 'not yet established' answer rather than a speculative number.

Confidential chair messages require explicit request and an allowed channel. Use exact quotations plus demonstrable factual/procedural discrepancy and its relevance. Do not allege motives, incompetence or misconduct from ordinary disagreement. Drafting never authorizes submission, reviewer contact or private-data upload.
