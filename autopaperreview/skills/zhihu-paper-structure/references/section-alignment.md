# Cross-Section Alignment and Local Repair

Independent operational extension of the separately attributed macro writing Skill.

## Section Contract

| Section | Reader must recover | Check against |
| --- | --- | --- |
| Abstract | Problem, supported contribution, result and conditions | Actual method and result tables; limitations on guarantees |
| Introduction | Gap, challenges, final answer and contribution ownership | Method opening and each contribution's evidence |
| Related work | Relevant comparison dimensions and inheritance | The actual cited work, not a convenient caricature |
| Method opening | Full component outline, inputs, interactions and output | Later definitions, figures and implemented behavior |
| Method details | What each step does, assumptions and boundaries | Algorithms, predicates, state transitions and available code |
| Experiments/results | What was measured, comparison and interpretation | Protocol, numeric tables, denominators and actual control variables |
| Discussion/conclusion | Supported takeaway and remaining limits | No stronger claims than abstract, method or results |
| Figure/caption | Same entities and completion status as the body | Source text plus actual rendered asset when available |

Maintain a terminology map: one term per entity, with any necessary aliases explicit. A renamed component must not silently acquire a stronger capability. Label design-only, implemented and measured claims distinctly. Material in an inactive appendix does not automatically support the submitted main paper.

Do not confuse reader-facing organization with the author's revision checklist. A contribution paragraph should explain the supported final mechanism, not list every unimplemented feature. Put necessary scope boundaries near the relevant claim and consolidate broader limitations in Discussion; preserve precise missing-evidence requests in the author-facing ledger. Keep the abstract's challenges aligned with the introduction rather than polishing two incompatible stories separately.

## Bounded Revision Procedure

1. Identify the existing comment and intended scientific message.
2. Read the complete story, but mark only authorized target paragraphs and necessary consistency dependencies for editing.
3. Draft the smallest coherent explanation. Put the operation before parameter inventories and replace vague benefit language with its actual supported role.
4. Recheck the revised wording against the original evidence and the rest of the manuscript. Check that no new loop, guarantee, experiment or novelty claim appeared.
5. Record exact before/after locations and any remaining evidence gap. A clear paragraph does not complete an unimplemented mechanism.

Synthetic acceptance check: a reader can identify what is recorded, what is selected and what is evaluated without looking several pages ahead. This is a comprehension test, not a numerical score or guarantee of acceptance.
