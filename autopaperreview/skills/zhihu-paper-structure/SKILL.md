# Paper Structure and Contributions

For a whole-paper writing pass, first state the central distinction in one sentence, then map each named mechanism to its purpose and evidence. Check that the abstract, introduction, method overview and conclusion tell the same story. A component count is not its contribution; a distinctive name must clarify a supported mechanism, not exaggerate it. Keep editorial diagnostics outside the manuscript and retain genuine scientific limits in the right section.

## Select the Right Pass

Read [the argument-to-revision playbook](references/argument-to-revision.md) for central-story repair, contribution rewriting, and evidence-grounded research presentations. It specifies section-level repairs and closure tests. These details are independent operational extensions, not additional claims about the source article.

For introduction/method restructuring read [narrative design](references/narrative-design.md); for cross-section checks read [section alignment](references/section-alignment.md). The existing [structure worksheet](references/structure-worksheet.md) provides a compact diagnostic record. On a local sentence edit use only the affected dependency check, not unsolicited global reorganization.

This Skill owns the argument and contribution outline. The application's **writing** module applies authorized text changes; **claims** validates evidence, **review** tests the resulting story and the micro Skill checks prose. Return a problem/challenge/mechanism/evidence map, the smallest supported reorganization and remaining scientific blockers. Do not replace a scientific gap with a fluent story.

- Present the final method before the research chronology. Explain the problem, the proposed mechanism and the supporting evidence without requiring the reader to reconstruct failed intermediate designs. Preserve scientifically relevant negative results in analysis rather than hiding them.
- Make contribution ownership explicit. Distinguish the author's new framework or modification from inherited components and common practice. Do not manufacture novelty by renaming an existing combination, omitting attribution or mechanically banning “based on.”
- Concentrate the complete method outline in an easy-to-find place. The abstract, introduction and method opening should agree on component roles; later subsections should elaborate that outline rather than introduce a different story.
- Explain why each component is needed and what it changes. A list of component names is not an explanation. A component's asserted benefit needs evidence; request the missing comparison instead of inventing an ablation or claiming causality from a full-system result.
- Make important insights and results explicit rather than expecting reviewers to infer them from dense tables. Use conventional section roles where appropriate, without forcing every paper into one template.
- For a local comment, check its dependencies against the whole paper but edit only the authorized passage. Report a concrete mismatch with location, reader impact and the smallest defensible repair. A narrative repair does not prove the scientific claim or complete an unimplemented mechanism.

Never turn the source's anecdotes or historical examples into facts about this manuscript. Preserve citations, measurements, equations and the author's intended scope.
