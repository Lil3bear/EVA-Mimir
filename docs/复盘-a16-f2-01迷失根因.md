## 二、迷失根因（两题同一类病）

### 根因：先入为主的错误假设

**f2-01**：
- 错误假设：flag 前缀是小写 `flag{`（题目 flag_format 也写小写）
- 实际：flag 是大写 `FLAG{`
- 后果：枚举授权码时写死 `target=b'flag{'` → 0 解 → 误判"无解"
- 修复：`embedded-license.md` / `algorithms.md` / `solver-and-dynamic-analysis.md` 三处加"flag 前缀可能是大写 FLAG{"警告

**a-16**：
- 错误假设：flag 在 gateway 的 `/api/v1/ranges`（被"agent token"干扰）
- 实际：flag 在 internal-api 的 `/admin/info?token=internal_admin_token_2024`
- 后果：花几十轮爆破 gateway 的 agent token（Header/query/SSH 全试），而漏枚举 internal-api 的 `/admin/*` 路径
- 修复：`ssrf.md` §7 写入完整正确链 + "gateway 是干扰项"警告

**b-01 flag3/4**（未解，同样的病）：
- 错误假设：把 hint 的"注意 SSH 服务"理解为"爆破 jump 的 SSH 密码"
- 实际：爆破 top3000 + 题目相关密码 + 5 用户全失败，说明爆破不是预期解法
- 未修复：正确解法尚未找到

### 共性规律

1. **"先入为主"是最大敌人**——一旦认定一个方向（flag 格式、flag 位置、利用方式），就会在那个方向死磕，漏掉真正简单的路。
2. **枚举必须系统全面**——a-16 漏了 `/admin/info`（带 token 的隐藏路由），f2-01 漏了大写 `FLAG{`。
3. **CTF 题不依赖爆破**——密码爆破（SSH、登录表单）几乎总是错误方向；凭证一定在"信息泄露"里。
4. **拿到 token/配置后，第一反应应该是"枚举该服务的所有带参数路径"，而不是"去别的服务找 token"**。
