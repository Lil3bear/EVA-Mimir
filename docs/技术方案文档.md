# EVA-Mimir — 基于大语言模型的自动化 CTF 攻防 Agent

## 技术方案文档

---

## 1. 项目概述

EVA-Mimir 是一个基于大语言模型（LLM）驱动的自动化 CTF 解题 Agent，旨在参加百度 BSRC「Agent+ 攻防能力挑战赛」。系统能够自主完成 CTF 题目的分析、漏洞发现、利用构造和 flag 提取全流程，覆盖 Web 渗透、二进制漏洞利用、密码学攻击、多阶段渗透、云安全攻击和对抗规避等六大攻防维度。

核心设计理念：**Solver + Observer 双角色架构**。Solver 专注于推进解题攻击链，Observer 作为旁路审查员防止 Solver 陷入死循环或误判方向，两者通过 Memory + Ideas 看板进行异步协作。

## 2. 技术架构

### 2.1 整体架构

         ↕ REST API

│  • 生命周期管理：超时/异常自动关闭                  │
│  • 汇总报告输出                                    │

### 2.2 运行模式

系统支持两种运行模式，启动时自动检测：

1. **Tsecbench 比赛模式**：检测到 `BENCHMARK_TOKEN` 环境变量时，Scheduler 自动从平台获取题目列表，逐题解答。
2. **Host Bridge 本地模式**：通过 Docker stdin/stdout 与 Host 进程通信，支持单题调试。

### 2.3 LLM 接入

使用 OpenAI SDK 兼容接口，支持通过环境变量 `LLM_BASE_URL` 和 `LLM_API_KEY` 配置任何兼容 API。比赛平台的网关地址（`*.tsecbench.gw`）通过环境变量注入，代码无需修改。

## 3. 核心算法与方法

### 3.1 ReAct 推理循环

Solver 采用 ReAct（Reasoning + Acting）范式：每一轮 LLM 先推理当前状态和下一步计划，然后调用一个或多个工具执行具体操作，最后观察工具返回的结果。整个过程由 `tool_choice="required"` 强制确保每轮必须产生工具调用，避免空转。

**关键设计**：
- 首轮强制流程：读取 Skill 指南 → 搜索 writeup（困难题）→ 首次 HTTP 探测
- 连续 3 轮无工具调用时自动 nudge（注入具体命令提示）
- flag 提交成功后立即终止，不浪费后续轮次

### 3.2 Observer 旁路审查机制

Observer 是本系统最核心的创新点。它以独立 LLM 会话运行，不共享 Solver 的对话上下文，避免陷入相同的推理惯性。

**触发机制**：
- **周期触发**：每 6 轮自动审查
- **事件触发**：Solver 请求 hint、approach 循环达到阈值时立即触发
- **无进展触发**：所有 ideas 均 failed 时快速路径强干预

**纠偏原则**：
- **只做方向性判断，禁止技术性判断**。Observer 没有 bash 执行能力，无法验证技术细节，历史上曾因技术性误判导致 Solver 20+ 轮空转。
- 纠偏消息在下一轮**开头**注入（而非上一轮末尾），确保 Solver LLM 在生成响应前必须看到。
- 内容指纹去重：相同方向的纠偏只发一次。

### 3.3 语义上下文压缩

LLM 上下文窗口有限，长题目（50+ 轮）早期发现会被滑动窗口截断。本系统在消息数超过 35 条时，先用 LLM 生成四要素状态摘要（突破口、凭据、当前路线、失败路线），再保留最近 20 条消息，摘要注入压缩后的头部。

**特殊处理**：Observer 纠偏消息从历史中单独提取，压缩后固定钉在消息末尾，防止被滑动窗口裁掉。

### 3.4 多层重复操作检测

防止 Solver 在死路上空转的三层检测机制：

1. **命令级**：对命令前 80 字符做指纹，同一指纹出现 ≥3 次时输出警告。
2. **Approach 级**：提取 URL 路径 + 参数名结构（忽略参数值），同一攻击模式出现 ≥5 次时警告并触发 Observer 审查。支持 curl 命令和 Python inline 脚本两种形式的 URL 提取。
3. **目标不可达**：同一 host 连续连接失败 ≥3 次时阻止继续重试，强制调用 `challenge_get_state` 确认 URL。

### 3.5 Memory + Ideas 状态管理

- **Memory**：分为 fact（已确认事实）、evidence（攻击证据）、failure（失败边界）、note（备注），上限 12 条。Observer 负责矛盾检测——新事实与旧条目冲突时必须先 memory_update 纠正，禁止并存矛盾事实。
- **Ideas**：攻击方向看板，状态流转为 pending → testing → verified/failed。Observer 标记 failed 前需确认是整条路线失败还是子分支失败。每 6 轮自动向 Solver 注入状态快照。

### 3.6 目标不可达协议

CTF 靶场环境可能因网络波动导致目标临时不可达。系统设计了分级响应：第 1-2 次失败记录并重试，第 3 次起强制停止访问、调用平台接口确认 URL 状态，避免盲目重连浪费 50+ 轮。

### 3.7 Skills 知识库

将各类 CTF 题型的攻击知识预编译为结构化的 Markdown 指南（SKILL.md），覆盖 7 个方向：

| Skill | 覆盖内容 |
|-------|---------|
| Web | SQL 注入、XSS、文件包含、SSTI、JWT 伪造、文件上传、SSRF |
| Pwn | 栈溢出、ROP、ret2libc、格式化字符串、堆利用 |
| Crypto | 古典密码、RSA 攻击、AES、哈希、数论 |
| Reverse | 静态分析、脱壳、算法还原、Z3 约束求解 |
| Pentest | 多阶段渗透、权限提升、横向移动、Docker 逃逸 |
| Cloud | 云元数据利用、S3 桶、Kubernetes 攻击、IAM 提权 |
| Evasion | WAF 绕过、编码绕过、文件上传绕过、disable_functions 绕过 |

Solver 在首轮根据题目类型加载对应 Skill，遇到 WAF 拦截时追加读取 Evasion Skill，实现知识的按需加载。

### 3.8 安全知识搜索

对于 Skill 未覆盖的冷门漏洞或 CVE，系统内置 `security_search` 工具，通过 LLM 生成安全知识查询结果。困难/中等题目强制在第 3 轮前搜索 writeup。返回结果中的数值类数据（hex 字节、碰撞对等）标注为可能不准确，要求 Solver 用 bash 本地验证后才能使用。

## 4. 多题调度策略

Scheduler 从 Tsecbench 平台获取全部题目列表后：

1. 按难度排序（easy → medium → hard），优先解决容易得分的题目
2. 跳过已完成的题目
3. 逐题执行生命周期：start → SolverAgent.run → close
4. 超时或异常自动关闭，记录失败原因
5. 最终汇总输出总得分、各题解题轮数、成功/失败/部分完成状态

## 5. 创新点总结

1. **Solver + Observer 双角色架构**：业界少见的旁路审查设计，有效防止 LLM 推理惯性导致的死循环。Observer 独立会话、方向性纠偏、内容指纹去重的三重保障。

2. **失败态精确区分**：针对 PHP highlight_file 类题目，系统精确区分"旁路成功但变量为空"和"条件比较失败"两种外观相似但本质不同的失败态，自动判断脚本确保每次请求后立即分类。

3. **三层重复操作检测**：命令级 + approach 级 + 目标不可达，从不同粒度防止无效重试。approach 级检测支持从 curl 和 Python inline 脚本中提取 URL 模式。

4. **语义上下文压缩 + 纠偏消息钉住**：解决长题目上下文丢失问题，同时确保 Observer 纠偏消息不被压缩裁掉。

5. **7 类 Skills 知识库 + 按需加载**：覆盖 CTF 全品类题型，Solver 按需读取，不预加载避免污染上下文。

6. **平台透明接入**：通过环境变量注入 LLM 网关地址和平台令牌，代码零修改即可在沙箱环境中运行。
