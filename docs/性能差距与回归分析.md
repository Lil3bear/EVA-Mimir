## 三、回归问题的本质：知识库"过拟合"而非"覆盖变体"

### 现象：之前能解，现在解不出

```
run-12752（8/26）：a-03 解出 +300、e3-04 解出 +225（那时是"基线"skills，无死路警告）
后来（9月）：a-03、e3-04 一直解不出（补了大量"死路警告"后）
```

### 根因：我们"基于最近失败补 skills"，导致过拟合

我们的迭代方式：
```
某题失败 → 分析卡点 → 补"死路警告/精确路径" → 再跑
```

问题：
1. **"死路警告"基于某次实例**（如 a-03 的 .144 Flask 死路实例）
2. **下一轮实例变了**（.146 是 pydash 正解）
3. 模型带着"死路警告"，遇到新实例**反而不敢试** → 回归

### 本质差异：死路结论 vs 多路径探索

| | 我们 | 第一名 |
|---|---|---|
| 知识库特点 | 基于最近失败，写"死路警告" | 覆盖所有变体，写"每种解法" |
| 遇到漂移实例 | "这是死路" → 放弃 | "换个路径试" → 继续 |
| 结果 | 回归 | 稳定（63/63）|

## 四、死路警告的副作用（具体案例）

我们在迭代中补的"死路警告"，实际上制造了回归：

| 死路警告 | 副作用 |
|---|---|
| a-03 "Flask 死路快速判定" | 模型一看 Flask 就放弃，不再探索（run-12752 时是自由探索才解出的）|
| e3-04 "二值死结，经典绕过无效" | 模型放弃经典绕过（实际是精确计数，修正后解出）|
| c-02 "git_url 回连死路" | 模型反复纠结 git_url，忽略 upload/pip 活路 |
| f2-05 "逆向瞎猜，跳过" | 直接跳过（第一名 8.3 分钟解出）|

**教训：基于单次失败下的"死路结论"，在实例漂移的靶场里是危险的。**

## 五、第一名成功的核心特征

1. **精准试错**：16 次失败 / 63 题 = 每题 0.25 次失败，几乎一击命中 → 极全的知识库
2. **耐心磨**：难题（b-02 94 分钟、c-03 40 分钟）靠长时间磨出来，不放弃
3. **多路径探索**：不写"死路"，每个题型写"每种变体的解法"
4. **不用 hint**：0 次 hint（靠知识库，不靠提示）

## 六、改进方向

### 1. 知识库改写法：从"死路警告"改为"多路径"

**错误写法**（我们现在的）：
```
❌ "Flask 死路，快速放弃"
❌ "经典绕过无效，不要试"
❌ "git_url 回连死路"
```

**正确写法**（第一名的方式）：
```
✅ "若是 Flask 实例 → flask-unsign 伪造；若是 pydash 实例 → 原型链污染"
✅ "先试经典绕过；若 triggered=5 再试编码绕过"
✅ "git_url 需回连（网络隔离不可用）→ 改走 upload + pip install"
```

### 2. 少写"禁止"，多写"替代"

- 不是"禁止路径枚举"，而是"路径枚举低效，优先 X"
- 不是"不要试 Y"，而是"Y 在 Z 条件下无效，先试 X"

### 3. 保留探索空间

- 每个"死路"结论都要加"若是实例漂移，检查是否有其他题型变体"
- 不要用"跳过/放弃"封死任何题的探索

### 4. 验证回归

- 每补一条"死路警告"，都要确认它不会让"之前能解的题"变成"解不出"
- 用历史成绩单（run-12752 等）做回归基准

---

## 七、核心结论

1. **本质是知识库差异**，但关键差异不是"多少"，而是"性质"：
   - 我们：过拟合到特定实例，补了太多"死路警告" → 回归、不稳定
   - 第一名：覆盖所有题型变体，多路径探索 → 稳定、63/63

2. **回归的根因是我们自己改 skills 改出来的**——"死路警告"让模型过早放弃。

3. **改进方向**：把知识库从"死路警告"改写为"多路径探索"，去掉"放弃/禁止"的束缚，保留模型的探索能力。
