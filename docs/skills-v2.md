# 写作 Skills 的职责与使用

## 这次修复了什么

此前本机三个知乎 Skill 已经有部分辅助工作表，但网页应用仍使用较早的入口文件，相关 MD 没有进入实际模型输入。另外，投稿规则直接加载了带有 ICLR 上下文的上游指南，容易与当前 WWW 论文不一致。

现在使用版本化的八模块职责表和逐模块工作表，三个知乎模块各自有明确的输入、判断、修复策略和完成条件。所有启用的资源文件由服务端实际读取，并在修订日志保存 SHA-256；不是只在 prompt 中写一个模型无法打开的路径。

## 八个基础模块

| 模块 | 具体工作 | 不应越权做什么 |
| --- | --- | --- |
| 学术表达 `writing` | 根据批注意图组织段落，先说明概念操作再解释实现细节，保持简洁 | 用漂亮措辞补造机制或实验 |
| 十维审稿 `review` | 全文理解后提出问题，再寻找最强反证，合并重复意见 | 为了严厉而制造问题或虚构官方评分 |
| 论断与证据 `claims` | 区分设计、实现、观测、受控比较和保证，校准归因与外推 | 用 may/suggests 掩盖没有依据的解释 |
| 引用核查 `citations` | 分开核对 Bib 语法、文献身份和引用支持关系 | 把本地解析成功说成全文核验或补造 DOI |
| 数学与符号 `math` | 检查定义域、更新规则、量词、空集、失败与缺失值 | 为了补齐表述而猜阈值和操作定义 |
| 双盲与复现 `blind` | 按实际规则检查身份信息；盘点真实版本、划分、预算、统计口径 | 自动运行实验、假定缺失信息或删除必要归属 |
| 投稿规则 `venue` | 按目标年份、track、阶段核对来源与要求；WWW 不沿用 ICLR | 宣称未核实的页数或匿名规则已经通过 |
| LaTeX 终检 `latex` | 精确定位、编译、渲染检查、版本与 Git 留痕 | 把编译成功等同于图像、科学性或批注均通过 |

完整英文职责表及逐模块 MD 位于 [contracts.md](../skills/modules/contracts.md)。一次调用可以组合这些模块，不代表必须调用八次模型。

## 三个知乎模块怎样配合

- **宏观布局**，丁霄汉，[原文](https://zhuanlan.zhihu.com/p/593195527)：问题、差距、挑战、机制、贡献归属和证据映射；检查引言、方法概览和结果是否讲同一件事。服务于写作、论断与审稿模块。
- **微观可读性**，丁霄汉，[原文](https://zhuanlan.zhihu.com/p/639732057)：逐段检查逻辑强度、防御弹性、迷惑时间、信息密度，配有具体诊断和作者风格检查。数学定义和引用真伪仍交给各自模块。
- **Rebuttal**，丁霄汉，[原文](https://zhuanlan.zhihu.com/p/602024489)：区分真实误解、有效批评、部分成立和缺证据；为审稿寻找合理反证，准备答复时给出可核对改动，不自动生成虚构评审或答辩。

出处属于原作者；判断表、八模块映射、合成例子、修改日志和作者偏好是独立工程扩展。未转载文章全文，不保留人身攻击、断章取义、装饰性引用或无证据推测的做法。

## 修改与完成不是一回事

每条意见沿用原 ID，记录原文、支持及相反证据、实际改动、编译、视觉检查和剩余问题。比如删除“controller 导致提升”的无依据归因可以完成措辞校准，但不能证明 controller 的独立收益；如果批注要求真实消融或库演变记录，该部分仍应待处理。

人工确认接口支持 `keepOpenCommentIds`：允许保存已改善的正文，同时将尚缺科学证据的关联批注保留在待处理栏，并把部分修改的版本写入日志与 Git。没有真实修改不生成“完成”；旧版本和失败编译不覆盖当前论文。

本轮沿用经济策略：本机 `gpt-6.1-sol`，不因技能数量增加而启用 Claude、Opus、Fable、Astra 或收费 API 备用通道。完整正文和 Bib 参与检查，类文件和 BST 仅用于编译，不浪费正文模型上下文。
